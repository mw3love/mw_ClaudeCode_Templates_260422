PRD 및 기초자료를 분석하여 구현 작업계획을 대화식으로 수립합니다.

트리거: `task-plan`, `작업계획`, `구현계획`, `task list`, `작업 계획서`, `태스크 플랜`

인수 없음. `/task-plan` 만 입력하면 `PRD/` 폴더를 자동 탐색하여 시작합니다.

---

**아래 단계를 순서대로 실행하세요.**

## 1단계: PRD 분석

프로젝트 루트의 `PRD/` 폴더를 탐색하여 모든 파일을 읽으세요:

```bash
find . -path "./PRD/*" -name "*.md" -not -path "./.git/*" 2>/dev/null
```

- PRD 파일이 **2개 이상**이면 에이전트를 병렬로 실행하여 분업 분석하세요 (예: 한 에이전트는 기획/목적, 다른 에이전트는 아키텍처/기술스택 담당).
- PRD 파일이 **1개**이면 단독으로 읽고 분석하세요.
- `PRD/` 폴더가 없으면 사용자에게 기획 문서 위치를 물어보고 중단하세요.

분석 결과를 아래 항목으로 요약하여 사용자에게 제시하세요:

```
## PRD 분석 결과

**프로젝트 목적**: ...
**핵심 기능 목록**: ...
**기술 스택**: ...
**아키텍처 / 설계의도**: ...
**주요 제약사항**: ...
```

## 2단계: 논의

분석 결과를 바탕으로 구체화가 필요한 사항을 **개방형 질문 목록**으로 정리하여 제시하세요.

다음 영역에서 모호하거나 미결된 점을 자동으로 판단하여 질문을 구성합니다:
- 기술 선택 불명확 (라이브러리, 패턴, 방식의 선택지가 여러 개인 경우)
- 복잡한 엣지케이스 (PRD 엣지케이스 테이블에서 처리 방식이 불분명한 항목)
- UI/UX 세부사항 (레이아웃, 사용성 관련 미결 사항)
- 성능 요구사항 (목표 응답시간, 대용량 처리 등 수치 미정인 경우)
- 기타 PRD에서 발견된 불명확한 요구사항

예시 출력 형식:
```
## 논의가 필요한 사항

1. [질문 내용] — [왜 명확해야 하는지 간략 설명]
2. ...
```

질문 제시 후 사용자의 답변을 기다리세요. 추가 논의가 이어지면 계속 응답합니다.

**사용자가 "계획 작성", "계획 써줘", "plan" 등의 표현으로 계획 작성을 지시할 때까지 이 단계를 유지합니다.**

## 3단계: 계획 초안 작성 (대화창 출력)

사용자가 계획 작성을 지시하면 실행합니다. **파일로 저장하지 않고 대화창에만 출력합니다.**

Phase 분할 기준:
- 각 Phase = 독립적으로 동작 가능한 기능 하나
- PRD의 모든 기능을 커버
- 의존성이 있는 기능은 선행 Phase에 배치

출력 형식:
```
## 구현 계획 초안

### Phase 1 — [기능명]
- [주요 작업 1]
- [주요 작업 2]
- 논의 반영: [2단계 논의에서 결정된 사항]

### Phase 2 — [기능명]
...

### Phase N — 통합 검증
- 전체 기능 연동 테스트
- 엣지케이스 시나리오 점검
```

초안 출력 후 피드백을 요청하세요. 수정 요청이 오면 반영하여 다시 출력합니다.

**사용자가 "task 생성", "task 만들어줘", "task list" 등의 표현으로 task 생성을 지시할 때까지 이 단계를 유지합니다.**

## 4단계: task-list.md 생성

사용자가 task 생성을 지시하면 실행합니다.

### 파일 경로 결정

```bash
# 오늘 날짜 확인
date +%y%m%d
```

- `task-list.md`가 없으면: 프로젝트 루트에 `task-list.md` 생성
- 이미 존재하면: `task-list_YYMMDD.md` 형식으로 날짜 버전 생성

### task-list.md 구조

아래 형식으로 작성하세요. PRD의 섹션 이름은 실제 PRD 파일의 헤더를 기준으로 `REF`를 작성합니다.

```markdown
# [프로젝트명] Task List
> 작성일: YYYY-MM-DD

## 개요
[PRD에서 추출한 프로젝트 목적 및 주요 기능 요약 — 1~3줄]

---

## Phase 현황

| Phase | 제목 | 상태 |
|-------|------|------|
| 1 | [기능명] | [ ] 미시작 |
| 2 | [기능명] | [ ] 미시작 |

---

## Phase 1 — [기능명]
> REF: PRD.md#[관련-섹션-헤더]

- [ ] **[태스크 제목]**
  - **수행 지침**: 구체적으로 무엇을 어떻게 구현할지 서술 (파일명, 함수명, 로직 포함)
  - **완료 기준**: Done When — 이 조건이 충족되면 완료로 간주
- [ ] **[태스크 제목]**
  - **수행 지침**: ...
  - **완료 기준**: Done When — ...
- [ ] **커밋**: `feat: [Phase 1 기능명 요약]`

## Phase 2 — [기능명]
> REF: PRD.md#[관련-섹션-헤더]

- [ ] **[태스크 제목]**
  - **수행 지침**: ...
  - **완료 기준**: Done When — ...
- [ ] **커밋**: `feat: [Phase 2 기능명 요약]`
```

### 완료 후 보고

생성된 파일 경로와 총 Phase 수, 총 태스크 수를 보고하세요.

구현 시작은 task-list.md를 열어 Phase 1부터 순서대로 진행하면 됩니다.
